## 3. Minimal domain/interface and persistence contract

Proposed source package layout (Builder can justify modest non-material naming changes; no code now):
- `src/shared/`: explicit versioned types/validators `Account`, `TransactionSource`, `SourceSnapshot`, `FreshnessCoverage`, `UserOverride` with stable opaque IDs, currency/units, source reference and observed-at synthetic time, nullable balances, pending, category/identity state. Calculation labels describe what the fixture totals include, not real spendable cash.
- `src/adapters/synthetic/` and `fixtures/`: committed deterministic invented accounts, transactions, fixture clock/ages and cases. Read-only `SourceReader` interface, zero Plaid SDK/token/API calls. The future real Plaid provider would implement a different separately gated adapter behind a security boundary, never import real creds into client or demo fixtures.
- `src/storage/`: `OverrideStore` interface and versioned local JSON implementation under a dedicated new ignored demo-state path with no existing-content overwrite or path traversal; initial state = no overrides. Persist only interpretations linked by immutable `transactionId`, not original source rows. Validate allowed category/label/notes and length/type, prevent overwriting source or inserting arbitrary ID. Serialize writes, write temporary file in same directory and replace atomically with recoverable old version; handle malformed/partial/corrupt file with a visible safe error and **no silent discard**; clean stop flushes. Fixture reset is explicit, reversible/confirmed where applicable; never wipe existing owner files. Tests use isolated temp directories.
- `src/server/`: minimal same-origin `GET` for fixture snapshot/list/detail, `GET` for joined effective view, `PATCH` for user override, optional explicit safe reset for synthetic state. Read-only source contract enforced at backend; reject invalid IDs/bodies with typed error; no external account writes. Binding only `127.0.0.1` for non-sensitive demo, no claim of financial-grade authentication, encryption or LAN safety. Do not use this development API to store future provider secrets.
- `src/client/`: Overview, Accounts, account detail, Transactions with semantic route navigation, predictable loading/status/error/success feedback, labels, accessible buttons/forms, narrow/mobile viewport usable layout. Source values versus user interpretations distinguishable; no fake “real-time” or “connected” badges.

**Basic invariants to test:** Fixture IDs stable across build/restart; source arrays/hashes remain unchanged after edit; override join is non-destructive, never excludes pending/unidentified data; per-account/all-account transaction sets reconcile; no double count from rendering the same record in multiple views; numeric totals have explicit sample basis and currency; no inferred unpaid bills, forecast or live available cash. All fixture bank names and amounts wholly invented. No personal finance data from the owner or linked tools.
