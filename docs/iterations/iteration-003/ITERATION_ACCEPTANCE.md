## Hard stops and authorization truth

1. **Roadmap contradiction:** if live Production experimentation is requested before the M0 host live-DB encryption/key/restore/protection preconditions, **STOP BEFORE FIRST API/LINK TOKEN**. Architect evaluates technical resequencing; if it materially changes the accepted G0→M0→M1 requirements or product/resource obligations, return through Creative/user and a fresh approved roadmap, not an unstated exception.
2. **Provider/cost incompatibility:** mandatory paid upgrade, owned domain/public receiver, standing online service, unapproved certificate/network privileges, absent eligible product or non-recoverable consent repair → STOP; present alternatives and approval owner, not an unsafe workaround.
3. **Privacy and safety:** uncertain bank permissions, absent explicit new financial consent, public/log/PR exposure of tokens/account or transaction data, unauthorized product/account expansion or two-Item creation → STOP and quarantine/minimize, then owner-directed secure response. Never collect a bank credential in Facet/ChatGPT.
4. **Honest proof:** a one-Item desktop initial link + mobile repair cannot claim **mobile initial** proof, and a benign update cannot claim remediation of a real `ITEM_LOGIN_REQUIRED` error. Missing mandatory physical proof remains BLOCKED; a report is not a release of the real capability.
