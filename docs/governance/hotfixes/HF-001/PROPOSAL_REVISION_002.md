## 3. F03 — universally scoped but role-separated owner PAUSE authority

A user's explicit direction **PAUSE <PauseID> for <scope and reason>** or affirmative acceptance of a presented pause scope is required; a complaint, “what's going on?” or unsolicited agent suggestion is **not** consent. Record the actual owner words, source/date, exact branch/head, scope (project, iteration, WP, review, approval wait), consequences and resumption conditions. If the ID is not yet known, publish a proposed stable ID first and require owner approval to bind it.

Three states are distinct:
- **SAFETY_STOP:** halt unsafe operations to the extent physically feasible immediately; no claim of repository pause or preserved WIP, and no retroactive owner consent. The affected role reports the stop and current facts.
- **PAUSE_REQUESTED / PAUSE_PENDING:** owner approved bounded pause but complete sanitized evidence and control commit have not been safely published; original active state may still be present in Git. All affected roles must voluntarily stop work, but UI state may not be claimed OWNER_PAUSED until control proof is complete.
- **OWNER_PAUSED:** only after the independent sanitized snapshot, owner approval receipt and exact guarded state-only pause control commit all exist, have correct ancestry and have been re-read.

**Snapshot responsibility matrix:** Current role documents only its own work facts and stops operations. If Builder is active, Builder may write a non-executing BUILDER_PAUSE_RETURN with exact source/test/dirty/untracked facts but does **not** set governance state or approve a pause; Clerk may mechanically verify/forward that technical receipt, never decide correctness. If Clerk is active, Clerk supplies administrative source/ref/approval facts; no technical materiality conclusion. If Creative is active, Creative supplies current product/decision facts; no Builder technical judgment. If Architect is active, Architect supplies its own plan/audit facts. If ActiveRole none at an approval wait or after SAFETY_STOP, Architect acts only under a **separately adopted, explicit owner-scoped OWNER_PAUSE_CONTROL_INTAKE exception**, not by pretending to be the previous active role. In every case, **Architect is the single deterministic pause-control publisher**, limited to capturing already-attributed role reports and owner consent; no authority to edit another role's source/test, reinterpret an approval, or resume work. When Architect itself is paused the owner-approved control exception permits administrative snapshot only, not ongoing work.

Before any pause commits, inventory: authoritative source ref and exact HEAD; current CURRENT_STATE blob and all fields; active/next role; iteration/WP and branch/baseline; exact plan/candidate/review/approval/BuilderTechnicalHead/PR/merge authorization/UAT state as applicable; current main HEAD; local worktree tracked/untracked/submodule changes or inability to inspect; external running services/credentials/cost/side effects; unresolved blocker and resume checks. No keys, secrets, personal financial data or unsanitized diagnostics in Git.

**Owner consent cannot silently cancel or extend** an implementation approval, PR exact-head merge authorization, support subscription, device consent, risk decision or deadline. Document their validity separately as UNKNOWN_PENDING_RECHECK until resume preflight.

## 4. F04 / C02-03 — exact pause publication phases, interruption and dirty WIP

A durable owner pause is a multi-step, two-ref process, **never one atomic transaction**; a pause ref alone is not a durable snapshot, owner approval receipt, or evidence of preserved local work.

**P0 — pause consent and WIP truth.** Verify original affected target branch T at exact HEAD H and original state blob, explicit owner-approved PauseID, scope, consequences and the authorized snapshot writer. Separate immediate SAFETY_STOP, PAUSE_PENDING and OWNER_PAUSED (§3). Inventory tracked dirty, untracked, unsaved, unavailable/unknown worktree files, current main and governing policy, open PR and exact merge authorization, Builder head/approval state and services or host side effects. Owner chooses whether WIP remains **local and not durably preserved** or a separate sanitized owner-approved preservation operation is verifiably performed. Unknown secrets, sensitive financial material, unsafe files or missing WIP proof cannot be represented as saved. A failure means truthful STOP / PAUSE_PENDING, never false OWNER_PAUSED.

**P1a — create-only claim.** From a freshly verified T=H, claim only `refs/heads/governance/pauses/<PauseID>` at **H** via a true atomic absent-ref create. The creation itself produces **CLAIMED_NO_SNAPSHOT**, not snapshot completion. Read-before-write absence is insufficient.

**P1b — snapshot X.** With pause ref still exactly H, original target T still H, owner's PauseID and original evidence/WIP/policy/consent fresh, create sanitized immutable `docs/governance/pauses/<PauseID>/PAUSE_SNAPSHOT.md` in a direct-child X of H on the pause ref. Guard the H→X publication with a verified expected-tip condition, then independently re-read exact remote ref, file blob, containing commit, original state, WIP caveats and main/owner/head identities. The initial H ref never means this X exists.

**Explicit P1a interrupted-phase classification (C02-03):**

- `ABSENT`: pause ref absent, no claim established; only a new verified P1a may create it.
- `CLAIMED_NO_SNAPSHOT`: pause ref **exists at exactly the original H** and has no `PAUSE_SNAPSHOT.md`. This is a recognized durable partial claim. Recheck exact original owner direction, PauseID, owner consent scope, target T=H, original state/blob, main and policy freshness, WIP inventory and no competing writer. **Only if all still match**, resume by guarded H→X P1b on the already-claimed ref. No ref deletion, alias, reset, force, second claim or invented owner approval. On changed or unverifiable facts, classify `PAUSE_PENDING_STALE / CONFLICT`, preserve ref and stop for explicit owner direction; do not claim work preserved or OWNER_PAUSED.
- `SNAPSHOT_X_MATCHING`: pause ref at exact direct-child X of H with verified snapshot blob and PauseID; revalidate target T, main, consent, WIP and expected owner approval status before P2.
- `APPROVAL_Y_MATCHING`: pause ref at Y direct child of X, with exact append-only owner PAUSE_APPROVAL receipt; revalidate T=H and original facts before P3.
- `PAUSED_P_MATCHING`: original target ref T at valid state-only direct-child P of H and pause ref at exact X→Y; read back and report OWNER_PAUSED **without replay**.
- `CONFLICT_OR_UNVERIFIABLE`: unexpected ref tip, snapshot content/path/ID mismatched, competing claim, changed target/main/policy/owner/WIP without reviewed recovery, missing remote confirmation; STOP, no automatic overwrite or permission.

**P2 — approval receipt Y.** Separately publish typed append-only `PAUSE_APPROVAL` as Y direct child of verified X on pause ref, binding exact owner wording, PauseID, snapshot blob and source T/H. Expected-tip X→Y guard and re-read mandatory; no duplicate approval record on replay. After X or Y but before P, classify PAUSE_PENDING.

**P3 — freeze target T.** After exact X→Y revalidation and T=H, create P direct child of H on original task ref T, changing **only `.project/CURRENT_STATE.md`** to `Phase GOVERNANCE; State OWNER_PAUSED; Iteration/WorkPackage retained; ActiveRole none; NextRole none; ApprovalRequiredFrom USER; ImplementationAuthorized false; Handoff` exact X/Y. Preserve original tuple/branch/baseline for future resume, recheck main/policy/owner facts, publish guarded exact-tip H→P and independently read the state. An older exact-head merge approval becomes stale when target head changes. Git cannot physically stop running services; record any remaining external effects.

**Crash and concurrency classifications:** After P1a before X = CLAIMED_NO_SNAPSHOT (not conflict if exact H, consent/facts fresh); after X or Y before P = PAUSE_PENDING; after verified Y and P = OWNER_PAUSED (idempotent). If target/main moves, WIP changes, owner consent becomes stale, or pause ref is ambiguous, stop and preserve evidence; do not force-create or overtake the other writer. One active/pending PauseID per scope. No automatic task resumption, implementation, merge or side-effect cancellation from receipt-only phases.

**Regression matrix additions:** HF10a crash after atomic P1a with ref=H, no snapshot and T=H returns CLAIMED_NO_SNAPSHOT and guarded recovery to X; HF10b same ref=H with stale T/main/policy/consent/WIP must STOP with PAUSE_PENDING_STALE; HF10c X/Y/P partial phases never duplicate approval or claim OWNER_PAUSED early; HF11 atomic collision preserves existing ref, no forced update; HF06/HF07 dirty/untracked WIP, unchanged PR approval and external effects cannot be misrepresented. T1 pure simulation is not proof of live CAS, actual owner consent or physical data preservation.
