## 3. F03 — universally scoped but role-separated owner PAUSE authority

A user's explicit direction **PAUSE <PauseID> for <scope and reason>** or affirmative acceptance of a presented pause scope is required; a complaint, “what's going on?” or unsolicited agent suggestion is **not** consent. Record the actual owner words, source/date, exact branch/head, scope (project, iteration, WP, review, approval wait), consequences and resumption conditions. If the ID is not yet known, publish a proposed stable ID first and require owner approval to bind it.

Three states are distinct:
- **SAFETY_STOP:** halt unsafe operations to the extent physically feasible immediately; no claim of repository pause or preserved WIP, and no retroactive owner consent. The affected role reports the stop and current facts.
- **PAUSE_REQUESTED / PAUSE_PENDING:** owner approved bounded pause but complete sanitized evidence and control commit have not been safely published; original active state may still be present in Git. All affected roles must voluntarily stop work, but UI state may not be claimed OWNER_PAUSED until control proof is complete.
- **OWNER_PAUSED:** only after the independent sanitized snapshot, owner approval receipt and exact guarded state-only pause control commit all exist, have correct ancestry and have been re-read.

**Snapshot responsibility matrix:** Current role documents only its own work facts and stops operations. If Builder is active, Builder may write a non-executing BUILDER_PAUSE_RETURN with exact source/test/dirty/untracked facts but does **not** set governance state or approve a pause; Clerk may mechanically verify/forward that technical receipt, never decide correctness. If Clerk is active, Clerk supplies administrative source/ref/approval facts; no technical materiality conclusion. If Creative is active, Creative supplies current product/decision facts; no Builder technical judgment. If Architect is active, Architect supplies its own plan/audit facts. If ActiveRole none at an approval wait or after SAFETY_STOP, Architect acts only under a **separately adopted, explicit owner-scoped OWNER_PAUSE_CONTROL_INTAKE exception**, not by pretending to be the previous active role. In every case, **Architect is the single deterministic pause-control publisher**, limited to capturing already-attributed role reports and owner consent; no authority to edit another role's source/test, reinterpret an approval, or resume work. When Architect itself is paused the owner-approved control exception permits administrative snapshot only, not ongoing work.

Before any pause commits, inventory: authoritative source ref and exact HEAD; current CURRENT_STATE blob and all fields; active/next role; iteration/WP and branch/baseline; exact plan/candidate/review/approval/BuilderTechnicalHead/PR/merge authorization/UAT state as applicable; current main HEAD; local worktree tracked/untracked/submodule changes or inability to inspect; external running services/credentials/cost/side effects; unresolved blocker and resume checks. No keys, secrets, personal financial data or unsanitized diagnostics in Git.

**Owner consent cannot silently cancel or extend** an implementation approval, PR exact-head merge authorization, support subscription, device consent, risk decision or deadline. Document their validity separately as UNKNOWN_PENDING_RECHECK until resume preflight.

## 4. F04 — atomicity, preservation and interruption of PAUSE

A completed durable PAUSE is a controlled **three-phase publication**, with one additional explicit owner-consent phase. A two-ref operation is *not* atomic: never imply all stages happened because the first did.

1. **P0 — Preflight and owner consent:** Authoritative active target branch T HEAD H and original state blob verified. Architect receives role-specific stop facts, owner explicitly approves exact PauseID and scope, and a classification of WIP: CLEAN; DIRTY_TRACKED / UNTRACKED / UNSAVED; or UNINSPECTED. Owner selects whether WIP remains local **without durable preservation** or is separately sanitized, independently reviewed and committed to an isolated owner-approved WIP snapshot ref with verified exact file list. Unsafe/uninspected WIP prevents a claim of “work preserved”; the user may choose an honest PAUSE_PENDING/STOP without a state publication. Never commit unknown financial secrets, backup keys or credentials. No hidden stash or auto-commit.
2. **P1 — Isolated snapshot ref:** atomically claim refs/heads/governance/pauses/<PauseID> from exact target H only if absent. Write immutable PAUSE_SNAPSHOT.md as first parented commit X with complete sanitized and bounded evidence; include ORIGINAL_BRANCH, ORIGINAL_HEAD, ORIGINAL_STATE_BLOB, MAIN_HEAD, role work evidence, WIP classification, owner consent source and PAUSE_ID. Verify X is published before continuing. A matching existing X is rehydrated; competing/different X = CONFLICT.
3. **P2 — Owner approval receipt:** separate append-only PAUSE_APPROVAL.md or typed scoped approval ledger commit Y directly child of X on the pause ref, binding owner exact words, PauseID, snapshot blob and original source head. No duplicates on replay. The original task ref T has not yet changed. Crash here is **PAUSE_PENDING**, not OWNER_PAUSED; a fresh process must observe both refs and revalidate all source facts before continuing.
4. **P3 — Freeze source ref:** from original target H, publish a **separate state-only guarded direct child P on T**, with Phase GOVERNANCE / State OWNER_PAUSED / Iteration unchanged / ActiveRole none / NextRole none / WorkPackage unchanged / Branch T / Baseline original / Handoff exact pause snapshot/approval identities / ApprovalRequiredFrom USER / ImplementationAuthorized false / ProjectLifecycle unchanged; include original tuple and PauseID to support exact restoration. Verify the observed old tip H before conditional update; no competing Builder commit is silently overwritten. The new commit P on T must change only CURRENT_STATE.md, and must be read back. It can change an open PR's head, so any older exact-head merge authorization is **STALE** until explicitly reapproved. No source code/tests or accepted roadmap edits in P.
5. A crash after P1 or P2 is an incomplete receipt, not a completed pause; resume same PauseID only after independent ref/H/WIP freshness checks. A crash after P3 must rehydrate exact X→Y and H→P and report OWNER_PAUSED idempotently. Only one pending/active PauseID per target scope; nested or competing requests are CONFLICT/OWNER_CHOICE_REQUIRED. No alias/ref deletion/rebase/force to “repair” a collision.
6. Continuing services/host effects cannot be frozen by Git. Record stop attempt, evidence and risks separately; any paid/privileged service changes require distinct owner consent. Existing remote PRs may remain open but no merge, Builder delivery, audit or Clerk clearance should occur while pause is active. Any manual or external branch movement invalidates simple resume.

**If P3 fails:** Remain PAUSE_PENDING with safe stop instructions, not a false completed pause. Recheck original T and owner authorization; do not force update, cancel someone else's work or silently make a second pause branch. An owner may approve abandonment of the incomplete pause after verifying effects; preserve the archival receipts.
